## 启动屏问题回归：根因是 autodl 上重新 build 冲掉了手工补丁

**现象**（用户 00:11 报告）：
- 3D 页面（/wisdom-space）刷新：先闪一下再深蓝
- 首页刷新：变成深蓝（用户要米白 boot-screen）

**诊断**（直接 curl 公网验证，不用猜）：
- `curl http://assistant3.cpolar.cn/` 发现线上 index.html 引用 `index-Bvh3P8rS.js`（新 bundle），而本地 8.20-0320 dist 是 `index-CxF-rbOQ.js`
- 线上 index.html 与项目根目录 Vite 模板 `index.html` 逐行一致（is-visible + 700ms 延迟模式）→ **有人在 autodl 上跑过 `npm run build`，dist 被模板重新生成，手工注入的路径感知补丁全被冲掉**
- 新 bundle 的 React 加载态是深蓝色 → 首页刷新变深蓝
- 线上 assets 里新旧两个 bundle 都在（CxF-rbOQ 也返回 200）——build 只加文件不删旧文件

**根治方案**（这次改模板源头，build 永远带上补丁）：
1. 根目录 `index.html`（Vite 模板）：在 `<style>` 前注入 `__PATH_AWARE_BOOT__` 脚本
   - 首页（/）：`html,body{background:#f8f5f0!important}` + boot-screen 立即显示（覆盖默认 opacity:0/700ms 延迟）
   - 非首页：`html,body{background:#0a0e27!important}` + `#boot-screen{display:none!important}` 第一帧深蓝
2. 本地 `dist/index.html`：从线上原样 curl 回来（保持引用 Bvh3P8rS，与服务器一致）再打同样补丁
3. autodl 上用 python3 heredoc 原地补丁 dist/index.html + 根模板（免 build、免 scp、幂等）

**关键认知**：
- 本地 dist 已过期（旧 bundle），以后**别用本地 dist 覆盖服务器**；更新前端 = 同步 src + 模板后在 autodl build
- 服务器 dist/index.html 被冲掉的历史教训：凡是手工改 dist 的补丁，build 一次就没——必须写进根模板
- `main.tsx` 无条件移除 boot-screen 的逻辑还在（bundle Bvh3P8rS 包含它，因为 src 同步过）
- 路由确认：只有 `/` 是米白首页，其余全部深蓝（App.tsx 82-98 行）

**待验证**：用户跑完 autodl 补丁后，浏览器硬刷新（Ctrl+F5）：
- `/` → 米白 boot-screen 第一帧出现，React 挂载后进首页
- `/wisdom-space` → 第一帧深蓝，无米白闪屏

## 00:24 用户报告：进入首页仍是深蓝（不是米白）

**已确认的事实**（用 curl 拉公网 + grep 线上 bundle）：
- 线上 `index.html` 包含 `__PATH_AWARE_BOOT__` 标记 → 路径感知补丁已生效
- 线上 `assets/index-Bvh3P8rS.js` bundle 包含 `style:{backgroundColor:"#f8f5f0"}`（2 处）→ LandingPage 硬编码米白确实在
- 线上 CSS 有浅/暗两套主题变量，浅色 `--color-background: 248 246 241` 是默认
- Express.static 响应头：`Cache-Control: public, max-age=0` + `Etag: W/"1248-..."` + `Last-Modified: Thu, 10 Sep 2026 16:19:48`

**最可能原因**：浏览器 ETag/304 缓存了旧的 index.html。
- `max-age=0` 不会让浏览器写磁盘强缓存，但浏览器的"内存缓存"在 F5 时可能直接复用
- 配合 ETag 的 304：如果用户之前打开过不带补丁的版本，缓存里那个版本会持续返回

**新加的根治**（`server/index.ts` 2391 行前）：no-store 中间件
- 对所有非 `/assets` `/uploads` `/api` 路径强制 `Cache-Control: no-store, no-cache, must-revalidate, max-age=0` + `Pragma: no-cache` + `Expires: 0`
- SPA fallback 返回的 index.html 也会被覆盖到（因为路径 `/wisdom-space` 不在白名单里）
- 部署后用户任何刷新都拿最新版

**诊断步骤**（让用户先自测）：
1. F12 → Network 面板 → 勾选 "Disable cache" → 刷新 `/` → 看是否变米白
2. F12 → Application → Local Storage → 看 `theme` 键的值（如果有，删了试试）

**部署 no-store 中间件需要的命令**（autodl 上）：
```bash
# 1. 上传本地 server/index.ts 到 autodl（scp 或 rsync）
# 2. 关键：用 fuser 按端口杀（pkill -f 'tsx server' 杀不掉孙进程）
fuser -k 6020/tcp
sleep 2
# 3. 启动新 server
cd /root/autodl-tmp/木雅语助手-8.20-0320
nohup npx tsx server/index.ts > server.log 2>&1 &
# 4. 验证 Cache-Control 已生效
curl -sI https://assistant3.cpolar.cn/ | grep -i cache-control
# 预期：no-store, no-cache, must-revalidate, max-age=0
```

## 00:44 重大根因发现：深蓝色是 LandingPage 内部 LoadingScreen 阶段，不是 boot-screen 没切对

**用户的实际观察（重新理解）**：
- 图 1 米白：`index.html` 静态 `#boot-screen`（红方块木字 + 加载中）→ **这部分是对的**
- 图 2 深蓝：圆形蓝头标 + "木雅藏语AI助手" + **完整副标题** + 进度条 100% → **这其实不是 boot-screen，也不是 LandingPage 的卡片选择页**——这是 LandingPage **内置**的 LoadingScreen 阶段

**用 inspect_bundle.cjs 反编译公网 bundle 得到的真相**：
- 线上 bundle `index-Bvh3P8rS.js` 里有个 minified 函数 `Obt`，完整结构是新版 LandingPage 的逻辑（带 `useFadeOutOverlay`、`useAssetPreload`、调 `ph`=`LoadingScreen`）：
  - `useEffect` fetch `/api/app-config`，状态机 `checking → ok/error`
  - `useAssetPreload` 预加载 `/screenshots/2d-preview.png` 和 `/screenshots/3d-preview.jpg`（15s 超时）
  - 进度：`s==ok && ready ? 100 : s==ok ? 50+m : m`
  - 渲染顺序：`error`→错误页 / `p=="show"`→`ph` LoadingScreen / `else`→米白 LandingPage 2D/3D 卡片
- **关键**：这版 LandingPage 是**有 LoadingScreen 过渡的**，会用深色的 LoadingScreen 组件当中间态
- 本地 `src/pages/LandingPage.tsx`（192 行）**不包含** `LoadingScreen/useFadeOut/useAssetPreload`（grep 计数 0），**直接渲染米白 2D/3D 卡片**

**根因**：
- 之前用户在 autodl 上跑过 `npm run build`，生成了 `dist/index-Bvh3P8rS.js`
- **autodl 上的 `src/pages/LandingPage.tsx` 当时是旧版**（含 LoadingScreen）
- 本地后来改过 LandingPage 去掉了 LoadingScreen，**但没同步到 autodl**，所以 `dist/assets/` 里那个旧 bundle 就一直 serve 旧的 LandingPage

**所以"先米白再深蓝"是真实的流程**：
1. 浏览器解析 HTML → 显示 `#boot-screen`（米白）
2. `main.tsx` 移除 boot-screen，挂载 LandingPage → 进入 LoadingScreen 阶段（深蓝）
3. 资源就绪 → 淡出 LoadingScreen → 显示米白 2D/3D 卡片

**服务器端验证**：
- `curl -sI https://assistant3.cpolar.cn/` → `Cache-Control: public, max-age=0`（**no-store 没部署**）
- `curl https://assistant3.cpolar.cn/api/app-config` → `{"appName":"木雅藏语AI助手","teacherName":"木雅语老师"}`（无 homeTitle）
- 即：no-store 中间件 9/11 凌晨 00:24 改的 `server/index.ts`，但**部署脚本用户没跑完**

**修复命令（这次必须 4 件事一起做）**：
1. 同步本地最新 `src/pages/LandingPage.tsx` 到 autodl（**核心，之前的方案漏了**）
2. 同步 `server/index.ts`（no-store 中间件）到 autodl
3. 同步根模板 `index.html`（已带 `__PATH_AWARE_BOOT__`）到 autodl
4. 在 autodl 上跑 `npm run build`，让 dist 从最新 src 编译（这才能保证 bundle 里的 LandingPage 没 LoadingScreen）
5. `fuser -k 6020/tcp` 杀旧 server
6. `nohup npx tsx server/index.ts > server.log 2>&1 &`

**教训（跨项目值得记住）**：
- 部署 React + Vite SPA 到远程时，凡是改 React 组件（tsx/tsx）必须 `sync src/ + npm run build`，**不能只 patch dist 文件**
- `dist/` 是 build 产物，`src/` 才是 source of truth；删/改 dist 永远会被 build 冲掉
- 加 no-store 中间件部署前必须验证响应头：`curl -sI https://xxx/ | grep cache-control`
